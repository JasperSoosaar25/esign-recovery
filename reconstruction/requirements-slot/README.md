# Original requirements-slot method body

Reviewed source translations of `-[YYYArchO generateSlotBuildRequirementsWithBundleId:subjectCN:]` (`0x100777638`, original ABI `@32@0:8@16@24`) and three native block invocations at `0x100777e78`, `0x100777f54`, and `0x1007781cc`. New C navigation names make these bodies independently compilable without fabricating the unfinished `YYYArchO` class. This adds no original class definition.

The code writes the original word sequence, UTF-8 strings with byte lengths and four-byte padding, the decoded `subject.CN` constant, and the ten-byte OID `2a864886f76364060201`. It then executes the already reconstructed `YYYBlob`, `YYYBlobIndex`, and `YYYSuperBlob` implementations. The exact original encrypted inputs and decoder instructions remain in evidence; source uses their decoded constants. Concurrent literal-initializer races and >4 GiB allocations are not verified.

A missing bundle ID or subject name returns **four bytes `fade0c01`**. The original applies `strlen` to a binary 12-byte vector and stops at its first zero. Empty non-nil strings take the normal construction path. This quirk is retained, not corrected.

`fixtures.json` records 117 comparisons generated by executing 1,983 distinct original instructions, with explicit Foundation/ARC host models: missing inputs, empty strings, Unicode, embedded NULs, all four padding residues, 64-bit word inputs truncated to 32 bits, and binary payloads.
