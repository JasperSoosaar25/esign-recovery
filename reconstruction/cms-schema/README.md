# Original CMS schemas, callbacks and LONG primitive

This component relocates the complete static descriptor graph reachable from the original `CMS_ContentInfo` item at `0x100b24750`: 53 items, 149 field templates, one seven-entry ADB table, ten auxiliary records and two function tables. All 257 graph nodes, including original names, offsets, flags, sizes, padding and every pointer relocation, are audited against saved original bytes. The previously recovered ANY item is reused; its existing name string is checked by bytes. The nine unreconstructed X509 callbacks/name codecs remain original external references.

Eleven original function bodies are translated: the five-instruction CMS BIO wrapper, five CMS auxiliary callbacks, and LONG new, free/clear, content decode, encode and print. The separate dispatch proof resolves the original CMS callback's four-byte jump table. All 267 distinct instructions execute in the comparison fixtures. Source-family references are in `reference-research.json`; original bytes and behavior take precedence over upstream source.

Run `python3 scripts/recover_cms_schema.py --verify`. Generation requires `--generate --original-ipa /path/to/the/exact/input.ipa`; it refuses other input hashes. The graph extractor, source renderer and pinned graph hash make descriptor changes detectable. On macOS, `python3 scripts/build_cms_schema.py` compares native behavior and compiles `libESignCMSSchema.a` for arm64 iOS 15.0. The archive contains only the two CMS source files, without test adapters or the original executable; link each preceding component once.

The 434 original-instruction/compiled-C comparisons include 108 actual CMS/parser compositions, 78 through memory BIO. All seven content types return their invented expected payload/ciphertext through the actual recovered CMS accessor and original OID lookup. Extended cases exercise all five recipient choices, signed/unsigned attributes, unknown OID fallback, constructed OCTET STRING and indefinite wrappers. These exercise parsing, not cryptographic verification, decryption or decompression. All 36 allocation sites of the invented signed message have a separate failure fixture, plus a successful out-of-range failure index. Tests compare decoded fields, complete bounded allocation state, cursor/slot/free-content changes, errors and callback effects, including post-cleanse/free field reloads.

Allocator/reallocator, reference locking, ex-data and ERR state are controlled test boundaries inherited from the preceding component. BN word bit-count and BIO formatting are explicit controlled boundaries for the LONG encoder/printer. CMS stream/data-init/data-final, key/certificate destruction and EVP context operations remain controlled dependencies. Any fixture reaching an unreconstructed X509 schema callback or name codec fails; no fake certificate parser is supplied. The test allocator fills new storage with `0xa5` and retains freed blocks for comparison; free events are checked, and the original value-free wrapper preserves the caller’s now-dangling slot. The stored `ASN1_OBJECT.nid` may remain zero even when the actual OID lookup resolves its encoding; ADB inspection uses that actual lookup.

A component-only build is not a complete CMS implementation, signing backend, application target, source-built IPA or iPhone run. Certificate-bearing CMS messages, original name/certificate/P12 routines, cryptographic streaming and most application source still need recovery. No runtime screenshots are claimed.
