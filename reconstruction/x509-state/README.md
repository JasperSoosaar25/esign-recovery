# Original X509 name, certificate and revocation-list state

This component supplies the nine X509 callbacks/name codecs referenced by the earlier CMS graph, plus thirteen supporting original bodies: X509/name-entry/string free wrappers, inner-stack cleanup, revoked comparison, tagged item entry, stack set/comparator/pop-free and BUF_MEM grow. It adds five original ASN.1 descriptors across fifteen audited nodes for nested names and ENUMERATED values, reusing the earlier CMS graph without duplicating its definitions. The original mutable CRL default-method pointer and its method table are relocated and checked.

Run `python3 scripts/recover_x509_state.py --verify`. Regeneration requires `--generate --original-ipa /path/to/the/exact/input.ipa`. Saved original instructions, recursively extracted descriptor bytes and original input hashes remain authoritative over upstream source-family names. On macOS, `python3 scripts/build_x509_state.py` compares native state and builds `libESignX509State.a` for arm64 iOS 15.0. This archive contains only the two new source files and excludes test implementations. All earlier archives must be linked once, with remaining original dependencies supplied.

All 456 original-instruction/compiled-C comparisons pass locally, exercising all 839 distinct instructions across the 22 bodies. The 79 parser composition cases include 73 direct nested-name cases, two certificate items, two CRL items and two memory-BIO-to-CMS cases containing both structures.

The comparisons exercise name allocation/freeing and nested RDN decoding/flattening, set indexes, exact input-encoding cache, modified-name grouping/re-encoding control, certificate cached-name cleanup, CRL IDP/reason/critical-extension/issuer state and live method callbacks. Actual recovered ASN.1 parsing, stacks, strings, OID lookup, object cleanup and CMS content access are composed with the new bodies. Invented DER cases include complete certificate and CRL structures inside a CMS message; these are syntax/state fixtures, not trusted or cryptographically valid certificates or signatures.

Original canonical-name generation (`0x100616178`), the ASN.1 encoding engine (`0x100618744`), name formatting/printing (`0x10061f458`, `0x100614624`), extension decoding, CRL hashing, public-key internals, several extension destructors, default CRL lookup/verification, allocation/refcount/ex-data and ERR remain controlled test boundaries. The runtime archive references those unresolved original symbols; it contains no substitute parser, formatter, canonicalizer or crypto engine. Parsing an invented name/certificate does not establish X509 validation or complete certificate/P12 support.

The test allocator uses deterministic `0xa5` storage and retains freed blocks for state comparison. Fixtures compare decoded fields, cursor/slot changes, ownership transfers and complete bounded allocation snapshots, plus call order and partial state after allocation/reallocation/callback failure. Original post-callback reloads, integer truncation, comparator sorted flags, caller-preserved versus cleared pointers and original error fallthrough are retained.
