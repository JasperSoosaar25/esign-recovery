# REA evaluation — 21 October 2026

The requested [morluto/rea](https://github.com/morluto/rea) was reviewed at main commit `aa51e4343963fdd0b97ec2ebdc3c41579fd9cb38`, including its Apple inventory and installation documentation. The latest published release observed was **rea-agents 6.7.0**, published 18 October. The newer main commit changes MCP schema advertisements; it does not establish new ESign source recovery.

REA 6.7.0 was installed separately from the app repository and actually run against the exact selected IPA. Its [sanitized result](research/rea-20261021.json) records the CLI fingerprint, original input hashes, inventory evidence IDs and Apple projection. The independent inventory accounts for 100 ZIP entries, with 97 deduplicated content nodes and 101 occurrences including the root. The Apple projection reports iOS, one application root, four bundles, one executable and ten JavaScript components, with complete coverage **within that inventory**. These are static inventory classifications.

On this Linux host, REA's `inspect-macho` operation returned `capability_unavailable`: that particular provider requires macOS utilities. No native decompiler was run through REA. Its Ghidra/Hopper/IDA integration can help future investigation when the corresponding engine is configured. The existing original-instruction analysis independently recovered the 640-instruction item decoder; that source was not generated by the inventory projection.

To reproduce with the pinned installed CLI:

```sh
npm install --prefix /path/outside/checkout/rea-tool --ignore-scripts --no-audit --no-fund rea-agents@6.7.0
python3 scripts/research_rea.py \
  --rea-entry /path/outside/checkout/rea-tool/node_modules/rea-agents/scripts/rea.mjs \
  --original-ipa /path/outside/checkout/esign_5.0.2_unsigned.ipa \
  --output /tmp/rea-esign-study.json
```

The script verifies both original hashes, performs inventory and Apple projection, and reports native inspection availability. It does not register an MCP server, alter agent configuration, execute ESign, upload the binary, or supply fake source. Temporary extracted bytes are removed after analysis. REA's inventory does not parse CMS semantics, reconstruct native methods, or produce an original-source app/IPA. See the [upstream Apple guide](https://github.com/morluto/rea/blob/aa51e4343963fdd0b97ec2ebdc3c41579fd9cb38/docs/apple-application-analysis.md) and [native investigation guide](https://github.com/morluto/rea/blob/aa51e4343963fdd0b97ec2ebdc3c41579fd9cb38/docs/native-investigation.md).
