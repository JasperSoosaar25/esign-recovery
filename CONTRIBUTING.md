# Contributing

Fork, create a branch, and open a pull request with a focused change. Recovery fixes, dependency identification, source reconstruction, test cases, documentation, accessibility, and future feature ideas are welcome.

For recovery changes, provide the exact input hash, original addresses/ABIs, script version, and reproducible evidence. Preserve baseline resources and generated output unless correcting a documented recovery error. Keep newly implemented source separate from machine-generated pseudocode.

For a new implementation, describe the trigger and expected behavior, assumptions inherited from decompilation, and meaningful tests. Include real device/runtime details for compatibility claims. Open a proposal before a large redesign or signing-pipeline rewrite.

Restore the two evidence snapshots with `python3 scripts/unpack_evidence.py` and `python3 scripts/unpack_native_methods.py`. Run `verify_repository.py`, `verify_original_flow.py`, `verify_app_analysis.py`, and `verify_native_methods.py` from `scripts/`, then run `recover_localization.py --verify`, `recover_scalar_accessors.py --verify`, `recover_signature_blobs.py --verify`, `recover_mach_header.py --verify`, `recover_entitlements.py --verify`, `recover_load_commands.py --verify`, `recover_recursive_der.py --verify`, `recover_requirements_slot.py --verify`, `recover_code_directory.py --verify`, `recover_legacy_crypto.py --verify`, `recover_rsa_wrapper.py --verify`, `recover_mobileprovision.py --verify`, `recover_cms_content.py --verify`, `recover_oid_lookup.py --verify`, `recover_bio_input.py --verify`, `recover_asn1_input.py --verify`, `recover_asn1_item.py --verify`, `recover_asn1_value.py --verify`, `recover_asn1_object.py --verify`, `recover_asn1_primitives.py --verify`, `recover_cms_schema.py --verify`, `recover_x509_state.py --verify`, `recover_asn1_encoding.py --verify`, and `generate_component_project.py --verify` from the same directory. Run `python3 -m unittest discover -s tests -v`. Install the pinned `requirements-reconstruction.txt` in a virtual environment to run all 184 tool tests and the compiled-C/original-ARM64 fragment comparisons. These validate recovery evidence, tools, twenty-two native components under explicit runtime/boundary models, and a narrow accessor subset; they do not verify the complete app. Follow [DEVELOPMENT.md](DEVELOPMENT.md), the original-only constraint in [BUILD-STATUS.md](docs/BUILD-STATUS.md), and the licensing boundaries in [LICENSE](LICENSE).

Do not commit IPA files, executables, provisioning/configuration profiles, certificates/private keys, passwords, pairing records, tokens, or identifying device data. Report sensitive findings through [SECURITY.md](SECURITY.md). Use invented fixtures in tests and redact device/certificate identifiers from issues and screenshots.

The new [component Xcode project](xcode/README.md) is deterministic build configuration for recovered source. Update `xcode/components.json`, regenerate, and verify it when adding an independently tested component. Preserve the existing runtime source once per archive; exclude test backend implementations. The aggregate Apple job builds all twenty-two libraries and records their hashes; individual jobs retain original-instruction/native behavior comparisons.
